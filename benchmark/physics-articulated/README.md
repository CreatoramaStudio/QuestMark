# Jolt vs PhysX: articulated-body physics tests

Correctness, onset-of-failure and determinism tests of two CPU physics libraries on articulated bodies with extreme mass ratios, fixed time step, float32:

- **Jolt Physics 5.7.0** (tag `v5.7.0`, commit `cf16769bb0ede9c45d57d06068ff0689e9702f5c`), bodies plus `HingeConstraint` / `SwingTwistConstraint` / `SixDOFConstraint` (maximal coordinates), used directly.
- **PhysX 5.13.0** as built from commit `7d6f6ac8b83e1610bdf715f1f2f1d6b718aee586` of the NVIDIA-Omniverse/PhysX repository (`physx/version.txt` reads `5.13.0.ae352bf5`; the repository has no tag named 5.13, so this is the head of its default branch at the time), `PxArticulationReducedCoordinate` (reduced coordinates). In some tests a PhysX maximal-coordinate variant (`PxRigidDynamic` + `PxRevoluteJoint` / `PxD6Joint`) is run as a control.

Both libraries are built from source clones (not included), CPU only (no GPU path), single thread unless stated, library-default solver settings unless stated, step rates 120 Hz and 200 Hz.

## Status of the results (read this first)

- **The results come from the original runs.** The sources were only renamed for publication (identifiers, folder and file names, labels). **No test was run again for this publication.** The ported sources were configured and compiled once (clang-cl, Ninja, RelWithDebInfo, all four executables linked, build log inspected for errors only) but **not run**; the original executables were built from the pre-rename sources, so equality of the ported code's behaviour with the original is not shown by a run.
- Identifiers in the JSON files were renamed (size labels, test names, field names such as `size_label`, `humanoid_*`), and the numeric values are unchanged. What else changed in the result files, exactly: the timing-validity note text was reworded to `NOT VALID FOR TIMING: machine was busy ...` (busy-machine files) and the idle-machine note now reads `idle machine, other applications closed, 1 session`; in 12 files of `chain-limb/results/followup/` the invalid JSON token `-nan(ind)` (one per file, a non-finite value) was replaced by `null` (the later harness already writes `null` for these); in `standing-foot` the three threshold keys that carried an internal test-number prefix became `anchor_onset_m`, `anchor_explosion_m`, `nonfinite_is_failure`. Every JSON file parses (`python -I -c "import json,sys;json.load(open(sys.argv[1]))" <file>`, 395 result files plus `common/sizes.json`).
- Evidence that the rename kept the data: the tables generated by the included `summarize.py` scripts from the renamed JSON files equal the tables of the original runs row for row (`standing-foot` `summary.md`, `ladder.md`; `table.md` and the `full-body` summary have the same rows in a different order because the rows sort by the new labels; the `chain-limb` and `hip-twist` numbers in this file were regenerated the same way and agree with the numbers in the original run notes).
- The `.log` files (printed output of every run) are **not included**; every number in this folder is in the JSON files and the generated summaries. Result files total about 7 MB.
- **Timings:** only the `chain-limb` main chain matrix (`chain-limb/results/*.json`: 12 matrix cases and 5 diagnostic cases) and the limb matrix (`chain-limb/results/limb/`, 96 cases) were timed on an idle machine (`timing_note` "idle machine, other applications closed, 1 session"). **All other result files were produced while the machine was busy; their timings are NOT valid** (`timing_note` "NOT VALID FOR TIMING: machine was busy ..."), and no timing claim is made for them. One machine, one session; desktop CPU class; no other hardware was tried.

## Test families

| folder | what it tests | scenes (identical in both libraries) |
|---|---|---|
| [chain-limb](chain-limb/README.md) | a 12-link chain with a 1000:1 end-to-end mass ratio (50 kg to 50 t), and limb chains (leg, arm) derived from the skeleton | chain launched at 30 m/s into a 5 cm wall; follow-up onset experiments (hinge axis, remedies, PhysX maximal control); limb cases hold, swing, wall, impact, worst-axis hold |
| [standing-foot](standing-foot/README.md) | two legs under a free, heavy pelvis standing on a ground box | two-leg and one-leg stance, a 2 t cube impact, a one-leg swing; library-default vs raised solver iterations |
| [hip-twist](hip-twist/README.md) | a 3-DOF hip/shoulder ball joint (swing + twist) with knee/ankle (or elbow/wrist) hinges | hold, swing, wall, impact, limits; four joint variants (two Jolt, two PhysX) |
| [full-body](full-body/README.md) | the whole humanoid (20 bodies, 19 joints) plus 500 debris cubes at a nominal 1000:1 mass ratio | stand, scripted step, step into debris, 2 t impact, arm launched into a wall |

Common code: `common/bench_stats.h` (small timing helper: fixed time step, warm-up excluded, mean, median, p99, p99.9, max of the per-step time; written for this folder), `third_party/ufbx` (the ufbx FBX reader, MIT/Unlicense, with its licence file), `CMakeLists.txt` (builds Jolt, PhysX and the four test executables).

## Metrics and thresholds

The metrics are computed by one code path from the body poses, for both libraries. **The thresholds are harness choices, not standards or requirements of either library.**

- Joint anchor error: distance between the two anchor points of a joint. Levels used: 0.01 m (onset is recorded), 0.1 m (flag level used for reading the data), 1 m (failure). Hinge axis error: 0.1 rad flag level. Any non-finite state is a failure; the step of its first occurrence is recorded.
- "Stays upright" (standing-foot): pelvis tilt never above 0.1 rad AND pelvis sag at the end below 10 % of the pelvis height AND the run reached its last step.
- "Explosion" (chain-limb): NaN, speed or angular speed above 100, or a joint error above 1 m.
- Tunnelling: a link centre behind the back face of the wall (full-body also reports "tunnelled corner": any arm-box corner behind it). Penetration: deepest box corner past the wall front face.
- Determinism: an FNV-1a hash over every body pose and velocity at every step (`trajectory_hash`) and over the final state; two or three runs from a rebuilt world in the same process must give equal hashes. Scope: same binary, same machine, same thread count.
- Step time (only where the machine was idle): the physics update call only, after warm-up, median and p99.

## Build and run

The tests need two things that are not in this repository: clones of the two libraries, and a humanoid skeleton FBX (below). Windows with clang-cl and Ninja was used (the CMake file contains the workarounds PhysX needs under clang-cl: it drops `/WX`, filters out UTF-16 `.rc` files, and defines the PVD macros by hand).

```
git clone --depth 1 --branch v5.7.0 https://github.com/jrouwe/JoltPhysics.git <jolt dir>
git clone https://github.com/NVIDIA-Omniverse/PhysX.git <physx dir>      # then check out 7d6f6ac8b83e1610bdf715f1f2f1d6b718aee586
cmake -S benchmark/physics-articulated -B <build dir> -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo \
      -DCMAKE_C_COMPILER=clang-cl -DCMAKE_CXX_COMPILER=clang-cl -DCMAKE_LINKER_TYPE=LLD \
      -DJOLT_DIR=<jolt dir> -DPHYSX_DIR=<physx dir>
cmake --build <build dir>
```

Executables: `<build dir>/chain-limb/chain_limb.exe`, `standing-foot/standing_foot.exe`, `hip-twist/hip_twist.exe`, `full-body/full_body.exe`. Either library alone also builds (set only one of the two variables). Only release-like builds give meaningful timings; PhysX is compiled with CMake's `RelWithDebInfo` flags (`/O2 /Ob1 /DNDEBUG`), not its own release flags (not measured whether this matters).

Run scripts (`run_*.sh` in each folder) take the build directory as first argument and are meant to be started from the repository root; set `OUT_DIR` to write into a new folder instead of the folder next to the sources (do not overwrite the published `results/`). The default size table path is `benchmark/physics-articulated/common/sizes.json` (relative to the repository root); `--sizes-json <file>` overrides it. Every test takes `--fbx <skeleton.fbx>`; **`--fbx` is required** for everything except the plain chain scene of `chain-limb` (`--scenario chain`, the default).

### The skeleton file (not included)

The body model came from a third-party humanoid skeleton file (FBX with a skinned mesh) whose licence does not allow redistribution. **It is not included**, and this repository contains no model or texture asset. The code reads the path given with `--fbx`. A compatible file is a humanoid skeleton FBX with a skinned mesh, bone nodes with these names (read by `chain-limb/limb.cpp` and `full-body/humanoid.cpp`; left side `_L`, the full-body test also the right side `_R`): `UpperLeg_L`, `LowerLeg_L`, `Ankle_L`, `AnkleReverse_L`, `Ball_L`, `Toes_L`, `Shoulder_L`, `Elbow_L`, `Hand_L`, bones starting with `Thumb_L`, `IndexFinger_L` (including `IndexFinger_L_04`, the arm tip) and `Finger_L`, and `Head`, `Eyes`, `Eyebrows`, `Jaw`. Every other bone counts as torso. The code derives joint positions from the bone world transforms and box sizes and masses from the skin weights, so the numbers in `results/` can only be reproduced with a file that has the same geometry; with another file the shape of the results may differ. The skeleton height used for the scale was 5.949 m (the dominant-weight vertex bounding box of the original file).

"Flag" means the 0.1 m / 0.1 rad levels above.

### chain-limb

| scene | Jolt | PhysX articulation | source |

Reading, scope-limited: in the alternating chain with the hinge axis parallel to gravity, Jolt lost joint closure and went non-finite within 4 s in 10 of 16 variant/rate cases, and none of the single remedies tried (constraint priority, body order, inertia multipliers, higher maximum angular velocity) cured it at 120 Hz; with the hinge axis perpendicular to gravity it did not. A PhysX maximal-coordinate control chain with the same masses also lost closure (error above 1 m at step 135 at 120 Hz) but did not go non-finite in 4 s, so the observed difference is between reduced-coordinate and maximal-coordinate formulation in this scene, not simply between the two libraries. On the limb chains (neighbour mass ratios 10:1 to 3:1 plus a 10:1 gimbal) both libraries finished every case. Idle timing of the 13-body scenes: median step about 0.017 to 0.025 ms for both libraries on one thread; in the limb matrix the worst per-case median was 0.0113 ms (Jolt) and 0.0133 ms (PhysX), the worst p99 0.048 ms and 0.146 ms; with 4 threads both were slower than with one thread (Jolt median 0.047 to 0.049 ms, PhysX 0.131 to 0.145 ms).

## Known limits

- One machine, one session, desktop CPU class; timings valid only where stated above. Nothing was run on any other hardware, no multithreaded runs except the 4-thread cases of the chain matrix, no double-precision Jolt, no PhysX GPU path.
- One skeleton; boxes (bounding boxes of the skin-weight groups) instead of the mesh; link masses from bounding-box volume shares (they over-count where boxes overlap); joint limits, PD gains and torque caps are assumptions of the harness (listed per test); hinge-only joints in the full-body test; no walking controller; no weight-transfer transition in the standing test.
- Body sizes, heights and masses are inputs from public fan-wiki figures (unit assumed), not measurements.
- The results are for these scenes and gain sets; for example the Jolt failures depend on solver iterations, step rate, hinge-axis direction and the mass-ratio chain, and were not isolated to a single cause. Hypotheses that were not checked are marked as such in the per-test READMEs.
- The PhysX version is the head of the default branch at the commit above, not a release tag.
- The ported sources were compiled but not run for this publication; the published numbers are from runs of the pre-rename sources.
